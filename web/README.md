# 商城前端

`dist/` 是原 LUMO 商城的完整可编辑前端源代码，使用原生 HTML、CSS、JavaScript，无打包依赖；图片位于 `dist/assets/`。页面风格和现有电商功能保留，业务数据改由后端服务保存。

Docker 中由独立 `web` 容器提供 HTML、JavaScript、CSS 和图片；同源代理 `/api/`、`/healthz`、`/readyz` 到 Go 网关。商城仍访问 `http://localhost:8080`，管理端为 `/admin.html`；网关 API 与 `/debug` 联调台默认在 `http://localhost:18080`。前端静态请求不会进入后端 Trace。

## 数据约定

- 业务状态、类型、角色、服务名、RPC动作和事件名在 `internal/constants/` 按领域维护。`go generate ./internal/constants` 生成只读的 `dist/constants.js`，前端通过 `window.LumoConstants.OrderStatus.Creating` 等分组引用；不要在业务脚本手写同一协议值或直接修改生成文件。纯前端状态投影单独定义，数据库及API已有字符串保持不变，测试脚本会校验生成同步与引用完整性。
- `api-client.js` 统一 JSON 命令、Bearer、幂等键、超时、Trace ID 和只读请求合并。默认同源，不自动连接其他主机。
- `skeleton.js/css` 提供统一的浅灰色图片、文字、价格、列表、优惠券、表单、统计和表格占位。商品首页/搜索/详情、购物车/结算/订单、活动/领券/推荐、分类/侧栏/评价问答、会员/客服及后台配置都按实际读取状态展示；成功为空才显示空态，失败保留重试，已加载内容后台更新时继续展示。占位没有可点击的假商品或价格，屏幕阅读器只播报加载状态，并遵循减少动态效果设置。
- `auth.js` 使用 IAM 登录、验证、刷新和撤销会话；旧原型的浏览器订单、积分、地址不导入后端。
- `app.js` 读取服务器商品和真实 SKU，金额以整数分转换显示；通过服务器不可变报价提交订单。订单成功页只在查询到后端接纳支付后显示。
- `member.js`、`services.js`、`promotions.js` 等模块保持视图模型，异步刷新服务器状态。库存不再根据浏览器订单推算，退款不自动当成退货入库。
- 商品规格对应独立 SKU，定价和库存由服务端校验。顾客不能调用内部预占、提交库存或订单支付裁决；演示模式下可通过 `payment/submit_demo` 提交本人支付单的模拟成功回执，沿用后端支付事件及资源确认链路，不产生真实扣款。
- 管理端使用独立的管理员登录会话处理演示支付、发货、售后、退款、审核和发票，顾客会话不会被自动替换成管理员。
- 活动入口包含秒杀、拼团、换购、满额立减、折扣特惠、多件优惠和限量直降。普通活动在商品详情、购物车或结算页选择，每单仅选一种，与换购互斥；资格预览和最终报价均调用后端，订单保留活动规则快照。
- 活动福利页的商品及“我的拼团”统一每页6项，顶部只显示总数与当前范围，分页统一放在列表底部；四类普通活动不再截断前12件。页数按当前已加载候选计算，翻页不读取接口；切换活动、场次、邀请或账号作用域回到第1页，刷新后夹紧已失效页码。购物车及结算中的换购选择保留内联展示。
- 首页提供领券中心入口与好券预览，仅加载第1页2张券预览。`#/coupons` 可匿名浏览全部已启用优惠券，使用 `templates_snapshot` 每页最多5000条加载完整元数据供可领取、限时和条件筛选；页面每页最多渲染6张券，桌面为3列2行，按领取状态和创建时间排序。普通 `templates` 仍限制每页100条。领取时登录，由后端校验时间、名额、可用积分与会员成长值；领取后的券在“我的优惠券”及结算页使用。
- `marketing-popup.js` 展示由后端决策返回的营销弹窗，支持红色、暖杏色与莓紫色主题、优惠券面额及门槛、延迟和可选自动关闭。首次访客、新老会员、高成长值会员、指定/排除用户、兴趣品类、积分与成长值区间、时间及页面条件均在“商城管理 → 营销弹窗”配置。新老会员依据IAM真实注册时间判断，单活动与全局频控同时生效；演示环境提供四种有条件的样例，正式环境不自动创建活动。
- 首次弹窗在公共内容就绪后独立请求后端决策；符合条件时在实际展示前增加一次曝光确认。后台标签页和已有表单不会消耗曝光，关闭后不会连弹下一条。登录、退出、页面或接口地址变化会取消旧响应与计时；领取必须经过本人投放凭证，失败可原凭证重试，成功后同步券包。仅领取成功时显示“立即使用”，进入页面不会自动发券。后台支持草稿、启用、暂停、复制、实时样式预览和展示/点击/领取统计，并通过版本校验防止覆盖其他管理员修改。
- 首页、商品分类、搜索、活动福利和领券中心通过 `storefrontPageStart()` 共用页头、主导航、安全留白与内容宽度，页面统一带 `storefront-page`。活动与领券使用紧凑标题，子筛选共用 `storefront-tabs`、底部分页共用尺寸和配色；不再单独使用大横幅。活动商品与其骨架跟随目录的6/4/3/2列，券卡与骨架使用3/2/1列；手机端标题操作纵向排布。切换页面保留整排导航，仅当前栏目显示选中态和下划线；手机端自动将当前项保持在横向可见区域。
- 首页左侧全品类目录由内容服务持久化配置，首次初始化包含20个大类、93个分组、586个细分入口。悬停、点击或键盘打开右侧面板，手机端采用横向入口和可滚动面板。分类、分组、搜索词、推荐标记、快捷入口、相关品牌及顺序均来自后端，前端没有静态分类树兜底；配置失败显示错误，空配置显示空态。
- 管理员可在“商城管理 → 分类导航”或“编辑商城 → 分类导航”配置上述内容，并添加、排序或隐藏大类。先编辑草稿，再保存并发布；重新加载商城时读取最新配置，重启服务不覆盖管理员修改。展示文案与商品实际分类字段分别编辑；隐藏导航不会移动或删除商品。
- 细分类目按一级类目与关键词联合查询，品牌入口按一级类目和品牌查询，筛选覆盖完整商品目录。搜索响应直接带商品元数据和实时库存，基础100件目录外的商品也能展示；查询结果池最多100件并淘汰上一批，保留购物车及正在查看的商品。尚无商品的类目显示空态，现有商品分类保持原值；编辑器的类目选择也扩展至20类。
- 演示模式额外初始化1,838件商品及3,676个独立SKU，覆盖20类、全部586个细分类及分组/快捷入口/配置品牌。每个细分类至少3款，另补80个分组主题组合；新增SKU初始库存50，后续价格、规格和库存以服务端实际记录为准。重复启动只补缺失商品，不覆盖管理员修改或重置预占/分配库存；原12件展示商品保留。没有对应实拍图的样例使用明确标注的中性品类示意图。
- 首页搜索采用连续红框的搜索区：聚焦展开本人搜索历史及两列搜索发现，可删除历史、换一换或直接搜索。发现词来自已加载的真实商品，聚焦和轮换不额外请求接口；输入关键词后在同一面板展示真实商品匹配。桌面面板与输入框等宽，手机端展开为页头可用宽度；展开不挪动分类导航和正文。点击外部、Escape、滚动及切换页面均关闭面板。
- 首页默认综合排序使用后端根据本人收藏、浏览、对比、搜索和已付款订单生成的推荐顺序，并展示实际推荐理由；匿名用户显示精选推荐。显式分类、品牌、关键词和销量/价格/新品排序继续优先。详情使用相似商品，支付后使用本人订单上下文，过滤已购商品。
- 推荐覆盖基础目录外的候选，按场景维护有界商品池；用户、令牌或网关变化会清除旧推荐并拒绝晚到响应。库存直接复用推荐响应的实时快照，以读取版本保护较新的库存状态；推荐失败不影响已成功加载的评价和问答。
- 桌面兴趣商品栏固定在浏览器左边缘，快捷工具固定在右边缘，中心内容在安全留白内扩展到最大1760px；侧栏收起与展开仅移动自身，中心区域的安全留白保持固定；左栏与同一个展开按钮使用平滑过渡，保留贴边展开入口并支持减少动态效果偏好。左栏由后端返回6件不同的真实商品，优先本人浏览/收藏，再按搜索、对比和购买等偏好推荐补位，最后使用有库存的精选商品；同款不同规格只占一个位置，没有行为或游客显示精选来源。只有可售目录本身不足6件或读取降级时才返回更少，不生成假商品。右侧继续提供首页、购物车数量、个人中心、客服、领券、足迹、意见反馈及回到顶部。折叠偏好保存在浏览器，个人商品数据仍由后端读取，账号、令牌或网关变化清除旧侧栏。平板及手机隐藏左栏并精简右侧入口，登录、编辑及交易表单页隐藏侧栏。

## 读取聚合与请求边界

`api-bootstrap.js` 将首页读取分为固定的业务展示分区。`storefront/shell` 只读取装修与分类配置；`storefront/products` 返回前100件公开商品及默认、规格SKU的批量实时库存；`storefront/activities` 返回活动、秒杀、拼团与2张券预览，并批量补齐活动商品和库存。公共装修、商品与会话恢复并行，会员服务较慢时仍能展示公共内容。分区各自保留骨架、错误与重试状态，展开分类面板不增加读取。

登录后的 `storefront/account_summary` 只提供页头和首页需要的资料、积分及券/收藏/购物车/通知计数。它是独立摘要模型，不会把完整会员、券包、收藏、购物车或通知列表误标为已加载。购物车件数、收藏数与通知未读数使用服务端独立SQL计数，列表仍最多100项，不用当前页条数冒充总数。失败字段保留 `null`；账号、令牌或接口地址变化清除旧摘要，普通换页在30秒内复用，相关写入后只重新读取受影响的域并投影计数。浏览和分析记录不会重拉六个账户域。

推荐使用独立的 `recommendation/list`，左侧兴趣栏使用独立的 `storefront/recent`，营销弹窗使用独立的 `storefront/popup`。最近兴趣一次返回最多6个真实不同父商品、默认SKU库存及来源；浏览或收藏变化后只刷新这个接口，收起和展开不触发读取。首页不会预载所有订单、地址、售后、发票、工单或FAQ。会员标签、商品详情、购物车、结算与支付按当前页面读取对应资源；启动中切换路由也会在结束后补齐最新页面所需数据。

`storefront/bootstrap` 仅保留为小型 `shell` 的兼容别名。通用 `storefront/batch` 已从HTTP白名单移除，客户端不再提交任意服务/动作列表。相同接口、认证作用域和参数的在途请求共享Promise，无关请求继续使用明确的业务地址。分区返回的快照只用于本轮初始化，结束后清除；切换会话或接口地址拒绝旧响应。空搜索复用已加载的商品；分类、品牌和关键词通过 `search/query` 查询完整目录，并返回批量库存。

同类商品与库存保留 `catalog/batch_get`、`inventory/batch_get`，每批最多500个去重SKU。缺失项与读取失败不会伪造库存，成功项独立保留；活动商品信息与库存并行读取，避免逐商品请求。接口、固定分区及结果格式见 `../docs/api.md`。

购物车进入时按每页100行读完本人列表；购物车、收藏、对比引用的商品超出首页目录时，再按SKU与父商品批量补齐元数据及库存。缺失商品明确不可用，不展示零价格的可结算占位；账号或接口地址变化会清除旧商品补齐与库存状态。

写操作、会保存结果的报价、订单与支付实时状态查询保持独立；写入后重新读取权威状态。支付成功页的稳定轮询只读订单，状态变化才刷新券、积分、购物车及订单SKU库存；领券仅刷新券包，取消订单只刷新其受影响资源。批量展示数据不替代下单时的价格、库存、优惠券和账户资格校验。

加载视图复用现有请求及进行中的Promise，不为占位发起额外读取，也不人为延长加载。首次请求、错误、成功空数据分别跟踪，按账号、接口地址与读取版本丢弃过期响应。冷启动进入首屏目录之外的商品详情时，目录完成后仅补一次指定商品读取，随后替换详情占位，不展示默认商品图、零价格或虚假的购买按钮。

## 单独部署

`web/Dockerfile` 只使用本目录作为构建上下文，独立生成 `lumo-mall-web:dev`，不需要 Go 或 Node 构建。
根目录后端镜像不再包含 `dist/`。运行 `sh start.sh web` 只构建/更新前端；默认增量检测也将页面资源、
Nginx 配置及入口脚本归属到 `web`，后端代码变化不会构建前端镜像。`WEB_PORT` 默认8080，
`GATEWAY_PORT` 默认18080，`WEB_GATEWAY_UPSTREAM` 默认 `gateway:8080`。

Nginx 通过 Docker DNS 定期重新解析网关，网关容器替换后无需重建前端。API请求保留方法、路径、查询、
请求体、Bearer、Cookie 与 Set-Cookie，浏览器继续使用第一方会话。前端自身的容器健康检查读取静态首页，
公开 `/healthz` 与 `/readyz` 仍检查真实网关。前端不注册业务RPC到Consul。

HTML及未版本化的静态文件使用 `no-cache` 重新验证。带 `?v=版本` 的资源可缓存1小时；文件名包含内容哈希
的静态资源可长期缓存。错误响应使用 `no-store`，缺失资源和未知API不会回退为首页；应用路由使用 `#`。

默认基础镜像为官方固定标签 `nginx:1.30.6-alpine`。Docker Hub不可达时，可设置
`WEB_NGINX_IMAGE=public.ecr.aws/docker/library/nginx:1.30.6-alpine` 使用同版本官方ECR镜像。
也可显式选择本机兼容的Nginx镜像并保留实际版本记录；修改此构建参数只重建前端。
`entrypoint.sh` 仅替换通过校验的网关 `hostname:port`，保留 Nginx 自身变量；只读容器仅将临时数据和生成配置
写入 tmpfs。默认镜像拉取仍需宿主机正常访问镜像仓库。

优先将本目录与 Go 网关同源部署。若单独发布前端，页面连接失败时可在“接口设置”填写 HTTPS 网关地址；网关需配置该前端来源的 `CORS_ALLOWED_ORIGINS`，对象上传则需配置 `MINIO_CORS_ORIGINS` 和实际可达的 `MINIO_PUBLIC_ENDPOINT`。更换接口地址会清除旧认证状态并要求重新登录。静态 Site 本身不运行 Go、MySQL 或消息队列。

营销弹窗需要稳定的第一方访客/会话Cookie。独立前端应将 `/api` 同源反向代理到网关；跨域API仍可使用Bearer，但不发送跨域Cookie，不能确认访客曝光时不会弹窗。Cookie只用于投放归属与频控，领取及管理操作仍需要服务端验证会话。

## 测试

```sh
sh scripts/test-frontend.sh
GOWORK=off go test ./tests -run TestHTTPStorefrontEndToEnd -count=1 -v
```

前一个命令在项目根目录执行，要求 Go、C 编译器、Node.js 22+ 和 curl。测试会创建临时数据库，启动真正的 TCP gRPC 服务及 HTTP 网关，按独立测试进程清理数据。它使用本地持久化事件派发器；完整 Docker 环境仍使用 RabbitMQ、MySQL、Redis、MinIO、Collector 和 Jaeger。

接口对应关系见 `../docs/frontend-api-coverage.md`，验收范围和基础设施限制见 `../docs/verification.md`。

独立前端代理回归使用已构建镜像和临时网络，验证会话、请求体、静态缓存、404和网关地址变化，完成后自动清理：

```sh
docker build -t lumo-web-proxy-test web
LUMO_TEST_WEB_IMAGE=lumo-web-proxy-test python3 tests/test_web_proxy.py
```

这项开发测试还需要Go编译一个临时HTTP测试服务；不修改运行中的Compose环境或真实`.env`。

## 商城浏览页展示约定

- 首页、分类筛选和搜索结果共用 `catalog-page` 页壳：红色页头、搜索、分类导航、内容安全宽度及商品卡密度保持一致；分类导航仅保留一份，并统一选中态。首页另有 `home-page` 展示主视觉、分类目录和会员福利，筛选结果不重复展示这些首页模块。
- “运营台”“编辑商城”和页脚“商城管理”仅向已登录管理员展示；编辑路由仍由认证模块与编辑模块检查管理员权限，隐藏入口不替代权限校验。
- 首页会员称呼、券数、积分和收藏数来自独立账户摘要。页头购物车数量优先使用已加载完整购物车，否则使用摘要；摘要缺少数据时显示未知状态，不构造虚假的空购物车或完整券包。`cartCount()` 仍只供实际购物车与交易逻辑计算。

## 后台管理布局

`admin.html` 使用独立的管理页壳：220px固定侧栏、64px顶栏及31个按业务分组的入口。900px及以下使用抽屉导航，选中菜单、遮罩、Escape或恢复桌面宽度时关闭。`admin-ui.js`复用加载、错误、确认、精确分页及会话隔离，`admin-operations.css`统一紧凑表格、详情、指标和表单。

`dashboard-admin.js`只请求独立的 `management/dashboard`，展示8项真实业务指标、7/30天收款退款趋势、待办、全量业务分布与快捷入口。累计指标和趋势范围明确区分；服务失败显示不可用，不用最近一页替代全量，也不编造同比环比。

`operations-admin.js`为订单、支付、仓储履约、售后、退款和发票各建独立控制器。统一服务端关键词/状态/日期筛选，每页20条，仅底部分页；详情按需读取业务单和关联订单，展示收货信息、商品、金额、权益及当前状态允许的处理。状态文案按领域分别维护，防止相同协议值在订单、售后、发票间串用。演示收款/签收/退款/开票明确标注；`management-admin.js`现负责异步账期对账，旧`reconciliation-admin.js`仅作兼容模块保留。

`inventory-admin.js`每页8件紧凑商品行，目录和名称搜索均为服务端分页，覆盖全部上下架商品。选择一个颜色/规格SKU后只展示该规格的在库、预占、分配、可售，调整后保留定位；历史兼容SKU保持独立库存。库存按最多500个SKU分批读取。近期20条调整记录每页5条，完整历史、出入库流水、阈值与全局缺货/低库存筛选位于“库存预警与流水”。`users-admin.js`支持账号分页、角色筛选、会员资料和有原因的普通账号启停，禁止操作自己及管理员；停用同步撤销会话，启用后重新登录。

其余评价、工单和行为列表仍明确标注有限读取范围，在本地筛选与底部分页。所有模块按接口/会话隔离，迟到响应不进入新会话；首次加载、成功空数据和读取失败独立表达，刷新失败保留已有数据。

## 前端设计与管理能力

保留模块化原生HTML/CSS/JavaScript，不引入组件库或构建框架。公共按钮、表单、弹窗、列表和骨架继续复用现有组件；后台业务模块分别维护商品、优惠券、活动、装修与内容，统一由admin页壳配置独立管理会话。

商城主色由 `--red` 驱动，`--red-dark/--pale/--brand-border/--brand-ring/--brand-fill` 等语义Token派生，首页页头、搜索、核心按钮、详情购买区及选中态随后台主题配置变化。错误/成功/警告和固定活动券面保持独立语义。后台统一 `--admin-*` 的色彩、字体、间距、圆角、控件与布局Token；以业务表格、平面快捷入口和统计重点区分信息，减少重复卡片套卡片。

手机主要操作区不小于44px高，数量按钮44×44，后台与弹窗输入16px；桌面保留紧凑密度。只读/禁用状态统一表达；弹窗关闭后恢复原触发器焦点，触发器已移除则不强行恢复。加载、错误、成功空数据分开表达，异步保存与后台刷新隔离，会话变化丢弃旧回复。

后台“优惠券管理”支持创建/复制/编辑、启停、领取窗口、积分/成长资格和增减配额；“活动管理”维护四类普通优惠规则，秒杀/拼团在独立菜单维护场次、规则及专用配额；“商品管理”提供真实服务器分页、编辑与上下架并保留规格；“商城装修”维护品牌主题、页头搜索、最多5张轮播、6个首页模块开关、公告和客服页脚；“内容管理”维护公告与FAQ。分类、弹窗和库存管理继续沿用已有真实接口。“会员与积分”“配送与运费”“通知模板”“推荐与搜索”“异常任务”“账号操作审计”均接真实管理接口；通知当前只投递站内信，不提供未配置的外部群发。

除既有前端/会员HTTP回归外，`scripts/test-frontend.sh` 现包含 `tests/frontend-admin-configuration.cjs`：单独临时库验证券创建/启用/领取/报价/增减库存/停用、营销创建/发布/报价、商品规格保留、装修与公告/FAQ及管理员权限。界面仍须用真实浏览器在桌面与手机宽度核对；CSS契约测试不能替代实际排版验收。

## 多类型权益与装修扩展

`coupon-benefits.js`统一四类券的金额/折扣券面、适用范围与整数分预估；后台支持满减、代金、折扣、满额折扣，可限制类目/商品及折扣封顶。券中心、首页预览、券包、弹窗和结算共用文案，最终使用资格和金额仍由后端裁决。已领取权益冻结；旧券字段缺失按原规则兼容。

`popup-admin.js`提供领券、公告、海报、新人礼、会员礼、活动六个内容预设，保持原有真实人群与频次条件。商城 `marketing-popup.js/css`按后端layout渲染，浅色主题和海报保持可读对比；不会对所有用户无条件展示。

`store-settings-admin.js`扩展装修配置，`storefront-layout.js`负责安全归一、轮播与模块可见性，`editor.js`保留相同配置。保存前合并最新文档，避免无关设置丢失；轮播可关闭自动播放，鼠标悬停、焦点、页面隐藏及减少动态效果偏好会暂停。隐藏分类或精选后为主视觉显式分配网格，避免刷新时缩为窄条。页面配置从内容服务读取，前端只保留默认值与渲染逻辑。

`scripts/test-frontend.sh`另包含 `frontend-admin-operations.cjs`，在独立临时库中验证工作台、管理员隔离、库存冲突与审计、4类券报价/提交、用户启停和配置校验；实际浏览器验收覆盖桌面和390px页面。运行环境的业务数据不用于写入测试。

后台长表格统一限高滚动、固定表头，键盘可聚焦滚动区域，分页位于区域外；长正文按需展开，交易长字段在详情中查看。对账差异每页8条、运行记录每页10条。后端管理扩展方向及当前能力边界见 [后台管理复查](../docs/frontend-api-coverage.md#后台管理扩展复查2026-10-28)。


`management-admin.js/css`统一管理新增能力：场次/成团规则、库存阈值和流水、会员补偿及规则、配送区域运费、业务通知模板、内容发布状态、推荐和搜索策略、账期对账、异常任务和账号审计。每次业务写入要求原因，配置带版本、补偿带旧余额和稳定幂等键；并发读取被API客户端正确识别为只读操作。规则、运费和积分奖励真实进入报价/订单/事件链路，历史订单使用快照。

新增后台集成测试：`go test ./tests -run TestAdminManagementIntegration -count=1`；前端模块契约：`node web/tests/management-admin.test.cjs`。功能、接口及外部适配边界见 [后台管理复查](../docs/frontend-api-coverage.md#后台管理扩展复查2026-10-28)。

## 登录、支付与购物提醒

系统设置新增“支付方式”“登录方式”开关。前台登录方法来自 IAM，支付方法来自 Payment，关闭渠道同时由服务端拒绝；微信/QQ 凭据缺失时不能启用。验证码在演示模式明确显示未发送短信，正式模式通过 SMS webhook 投递。

结算调用 `coupon/calculate` 默认使用最佳可用券，可切换手选或不用券。重新计价保留上一份金额并暂禁提交；不再反复替换金额骨架，晚到报价不能覆盖当前选择。

`product-alerts.js` 在商品页提供降价提醒和缺货到货提醒，`#/member/alerts` 每页10条管理本人订阅。`alerts-admin.js` 提供后台规则、开关、精确筛选分页和停用；检查任务从持久化数据恢复，每次触发投递一次站内消息。

详细能力、后续优先级与渠道边界见 [商城完善记录](../docs/commerce-improvements.md)。

## 后台行为与客服界面

`service-admin.js` 接入行为和工单独立管理页：行为记录显示中文动作、商品/搜索词、会员与时间，工单在右侧对话窗显示顾客/客服消息并直接回复，列表与消息均分页。`admin-details.js` 统一通用详情与处理结果，避免直接渲染JSON。票据记录导出使用可打印HTML；JSON仅用于装修技术备份。

`access-admin.js` 在开关下提供各渠道参数编辑，调用管理员 provider_get/provider_upsert，字段由服务端注册。私密字段不回显，留空保留，显式勾选可清除；渠道参数和开关各有独立版本。详见 `docs/login-providers.md`、`docs/payment-providers.md`。
