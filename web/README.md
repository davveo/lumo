# 商城前端

`dist/` 是原 LUMO 商城的完整可编辑前端源代码，使用原生 HTML、CSS、JavaScript，无打包依赖；图片位于 `dist/assets/`。页面风格和现有电商功能保留，业务数据改由后端服务保存。

Docker 网关直接提供这些文件和 `/api/v1/`，因此本地访问 `http://localhost:8080` 即可体验完整商城。管理端为 `/admin.html`，原接口联调台移至 `/debug`。

## 数据约定

- `api-client.js` 统一 JSON 命令、Bearer、幂等键、超时、Trace ID 和只读请求合并。默认同源，不自动连接其他主机。
- `auth.js` 使用 IAM 登录、验证、刷新和撤销会话；旧原型的浏览器订单、积分、地址不导入后端。
- `app.js` 读取服务器商品和真实 SKU，金额以整数分转换显示；通过服务器不可变报价提交订单。订单成功页只在查询到后端接纳支付后显示。
- `member.js`、`services.js`、`promotions.js` 等模块保持视图模型，异步刷新服务器状态。库存不再根据浏览器订单推算，退款不自动当成退货入库。
- 商品规格对应独立 SKU，定价和库存由服务端校验。顾客不能调用内部预占、提交库存或订单支付裁决；演示模式下可通过 `payment/submit_demo` 提交本人支付单的模拟成功回执，沿用后端支付事件及资源确认链路，不产生真实扣款。
- 管理端使用独立的管理员登录会话处理演示支付、发货、售后、退款、审核和发票，顾客会话不会被自动替换成管理员。
- 活动入口包含秒杀、拼团、换购、满额立减、折扣特惠、多件优惠和限量直降。普通活动在商品详情、购物车或结算页选择，每单仅选一种，与换购互斥；资格预览和最终报价均调用后端，订单保留活动规则快照。
- 活动福利页的商品及“我的拼团”统一每页6项，顶部显示总数、当前范围和快捷翻页，底部提供数字页码；四类普通活动不再截断前12件。页数按当前已加载候选计算，翻页不读取接口；切换活动、场次、邀请或账号作用域回到第1页，刷新后夹紧已失效页码。购物车及结算中的换购选择保留内联展示。
- 首页提供领券中心入口与好券预览，仅加载第1页100条模板。`#/coupons` 可匿名浏览全部已启用优惠券，使用 `templates_snapshot` 每页最多5000条加载完整元数据供可领取、限时和条件筛选；页面每页最多渲染6张券，桌面为3列2行，按领取状态和创建时间排序。普通 `templates` 仍限制每页100条。领取时登录，由后端校验时间、名额、可用积分与会员成长值；领取后的券在“我的优惠券”及结算页使用。
- 商品分类、活动福利和领券中心共用主导航，切换时保留整排入口，仅当前栏目显示选中态和下划线；手机端自动将当前项保持在横向可见区域。
- 首页左侧全品类目录由内容服务持久化配置，首次初始化包含20个大类、93个分组、586个细分入口。悬停、点击或键盘打开右侧面板，手机端采用横向入口和可滚动面板。分类、分组、搜索词、推荐标记、快捷入口、相关品牌及顺序均来自后端，前端没有静态分类树兜底；配置失败显示错误，空配置显示空态。
- 管理员可在“商城管理 → 分类导航”或“编辑商城 → 分类导航”配置上述内容，并添加、排序或隐藏大类。先编辑草稿，再保存并发布；重新加载商城时读取最新配置，重启服务不覆盖管理员修改。展示文案与商品实际分类字段分别编辑；隐藏导航不会移动或删除商品。
- 细分类目按一级类目与关键词联合查询，品牌入口按一级类目和品牌查询，筛选覆盖完整商品目录。搜索响应直接带商品元数据和实时库存，基础100件目录外的商品也能展示；查询结果池最多100件并淘汰上一批，保留购物车及正在查看的商品。尚无商品的类目显示空态，现有商品分类保持原值；编辑器的类目选择也扩展至20类。
- 首页搜索采用连续红框的搜索区：聚焦展开本人搜索历史及两列搜索发现，可删除历史、换一换或直接搜索。发现词来自已加载的真实商品，聚焦和轮换不额外请求接口；输入关键词后在同一面板展示真实商品匹配。桌面面板与输入框等宽，手机端展开为页头可用宽度；展开不挪动分类导航和正文。点击外部、Escape、滚动及切换页面均关闭面板。
- 首页默认综合排序使用后端根据本人收藏、浏览、对比、搜索和已付款订单生成的推荐顺序，并展示实际推荐理由；匿名用户显示精选推荐。显式分类、品牌、关键词和销量/价格/新品排序继续优先。详情使用相似商品，支付后使用本人订单上下文，过滤已购商品。
- 推荐覆盖基础目录外的候选，按场景维护有界商品池；用户、令牌或网关变化会清除旧推荐并拒绝晚到响应。库存直接复用推荐响应的实时快照，以读取版本保护较新的库存状态；推荐失败不影响已成功加载的评价和问答。
- 桌面左侧固定“最近感兴趣”商品栏，优先展示本人浏览足迹，再补充收藏；按前六个原始 SKU 加载并合并同款规格，展示真实图片、名称和价格。右侧提供首页、购物车数量、个人中心、客服、领券、足迹、意见反馈及回到顶部；反馈打开现有工单表单。两侧可收起并再次展开，仅显示偏好存入浏览器，不保存个人浏览记录；账号、令牌或网关变化清除旧侧栏。手机端隐藏左栏并精简右侧入口，登录、编辑及交易表单页隐藏侧栏。

## 读取聚合与请求边界

会话恢复后，`api-bootstrap.js` 调用 `POST /api/v1/storefront/bootstrap`，一次获取公开商城数据和已登录用户的账户数据。网关将已读取的本人行为、订单和商品/库存传给内部推荐排序，避免重复读取列表；首页推荐及新增推荐商品库存也在同一响应中返回。分类配置复用其中的装修内容列表，补齐 `content/get`、`id=storefront-categories` 的公共缓存；列表未包含该文档时仅在网关内部补一次固定ID查询。首屏等待分类配置后渲染，展开面板不再读取接口。现有模块从返回的命令结果加载状态；商品默认/规格、秒杀及购物车 SKU 的库存也由网关批量补齐。启动快照只供本轮初始化使用，结束后清除。空搜索复用已加载的商品；指定分类、品牌或关键词时通过 `search/query` 查询完整目录并返回批量库存。

左侧兴趣栏复用已验证的本人足迹及收藏，启动聚合预载前六个原始 SKU 对应的商品、父商品及默认库存，已有目录与推荐数据直接复用。目录外信息按批补齐，不逐条读取；访客没有额外读取，登录后仍只需会话恢复及一次启动聚合。新增浏览、移除或清空足迹以及收藏变化后，显式刷新侧栏元数据；纯渲染、收起和展开不触发接口。

共享 API 客户端会将同一轮并发的可合并读取发送到 `POST /api/v1/storefront/batch`，覆盖会员、购物车、详情、活动、服务及管理页面。相同请求共享进行中的 Promise，每批最多64个子请求；不同接口地址、认证模式、用户或管理员会话分开处理。切换账号、令牌或接口地址会使旧快照和请求作用域失效，避免账户数据串用。

网关先预检整个批次的只读白名单和每项权限，再以最多8个并发 RPC 执行；相同命令去重，部分读取失败单独返回。商品和库存按最多500个 SKU 合并为一次 SQL `IN` 查询，保留缺失 SKU 的独立错误。完整请求与结果格式见 `../docs/api.md`；诊断中的请求记录对应实际 HTTP 请求，批次包含子请求数和失败项信息。

库存模块直接按每批最多500个去重 SKU 调用 `batch_get`，避免100个商品因通用批次的64项上限拆成多次 HTTP。缺失或失败项会清除对应旧库存，保留同批成功结果；活动商品详情和库存同时读取，发票与红冲记录也在同一批返回。

写操作、会保存结果的报价、订单与支付实时状态查询保持独立请求；写入会使启动快照失效，后续读取重新访问服务端。批量读取不替代下单时的价格、库存、优惠券和账户资格校验。

## 单独部署

优先将本目录与 Go 网关同源部署。若单独发布前端，页面连接失败时可在“接口设置”填写 HTTPS 网关地址；网关需配置该前端来源的 `CORS_ALLOWED_ORIGINS`，对象上传则需配置 `MINIO_CORS_ORIGINS` 和实际可达的 `MINIO_PUBLIC_ENDPOINT`。更换接口地址会清除旧认证状态并要求重新登录。静态 Site 本身不运行 Go、MySQL 或消息队列。

## 测试

```sh
sh scripts/test-frontend.sh
GOWORK=off go test ./tests -run TestHTTPStorefrontEndToEnd -count=1 -v
```

前一个命令在项目根目录执行，要求 Go、C 编译器、Node.js 22+ 和 curl。测试会创建临时数据库，启动真正的 TCP gRPC 服务及 HTTP 网关，按独立测试进程清理数据。它使用本地持久化事件派发器；完整 Docker 环境仍使用 RabbitMQ、MySQL、Redis、MinIO、Collector 和 Jaeger。

接口对应关系见 `../docs/frontend-api-coverage.md`，验收范围和基础设施限制见 `../docs/verification.md`。
