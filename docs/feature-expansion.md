# 八项功能扩展

前台入口为 `index.html`，商家入口为 `admin.html`。以下能力均使用现有 HTTP 网关、具名 RPC 和各领域数据库，数据库迁移随服务启动执行，不需要删除或重新初始化数据卷。

## 1. 账号安全中心

会员进入“个人中心 → 设置 → 账号安全中心”，可修改密码、验证绑定手机/邮箱、查看最近 100 个有效登录设备并撤销指定设备。修改密码必须验证当前密码，新密码为 8–72 字节且包含字母、数字；修改或找回成功后撤销该账号全部会话。登录页的“忘记密码”通过账号已验证的联系方式找回。

验证码与账号、用途绑定，10 分钟有效，只能消费一次，最多尝试 5 次；同联系方式/用途每天 10 次、间隔至少 60 秒，同来源 IP 每天 50 次。找回接口不返回绑定地址，也不区分不存在、未绑定和渠道未就绪的账号。

手机沿用后台登录渠道的短信 webhook。邮箱使用 `IAM_EMAIL_WEBHOOK_URL`、`IAM_EMAIL_WEBHOOK_TOKEN`。安全验证码 webhook 接收 `{recipient,phone,code,purpose,ttl_seconds,request_id}`，用途为 `bind` 或 `reset`，认证方式为 Bearer token；返回 2xx 才标记已发送。生产须使用 HTTPS。仅在 `DEMO_MODE=true` 且渠道地址为空时返回页面明确标记的演示验证码；演示不会发送短信或邮件。

## 2. 游客购物车

未登录用户可以加购、调整数量和删除商品；结算时进入登录。浏览器只保存 SKU 与数量，按 API 来源隔离，30 天过期，最多 100 种 SKU、每种最多 10 件；展示时重新读取当前商品和价格。登录后调用现有购物车合并接口，保持幂等重试。失败时保留游客内容并显示“重试合并”，已下架/失效商品会明确提示跳过。跨账号的未完成合并不会自动串入另一个账号。

合并读取商品信息期间，若其他标签页修改购物车，本次合并中止并保留最新内容；切换账号或 API 地址也会中止旧请求的后续处理。密码、短信及微信/QQ登录均使用相同触发流程。

## 3. 经营分析

后台“工作台 → 经营分析”支持近 7/30/90 天：实际收款、退款、净收款、支付订单数、客单价、购买人数、复购比例、商品支付件数排行，以及浏览/加购/结算/支付的登录用户到达人数。统计时区为 UTC+8，复购指期间至少两笔支付订单；漏斗的交集人数不代表严格按时间顺序发生的转化。排行榜为支付件数，未扣除退货件数；净收款是现金口径，不代表会计利润。

新交易通过支付/退款成功事件幂等投影到分析事实表。旧数据可点“同步或继续同步历史交易”，按游标每次 25 条补录；单次界面最多推进 40 页，可继续点击，不会重复累计。历史退款缺少独立成功时间，使用成功单据的最后更新时间。历史浏览行为无法凭空恢复，只有启用后采集的登录行为参与漏斗。

## 4. 员工与权限

仅超级管理员能使用“员工与权限”，创建员工或将现有普通账号分配为固定岗位；支持停用、修改岗位并记录原因。修改会撤销该员工旧会话，不能通过员工表单修改超级管理员或自己。

- 客服：订单/售后查询、售后审核、工单回复和互动问答。
- 仓库：库存、采购、履约、物流轨迹和异常件处理。
- 运营：商品与导入、优惠券/活动、页面内容、推荐搜索策略和经营分析。
- 财务：支付、退款、票据、对账及经营分析。
- 分析：经营分析及必要汇总、商品查询。

权限通过服务端逐个 RPC 动作校验；前端菜单随岗位显示。财务、分析和超级管理员可导出已授权数据，其他岗位不开放导出。超级管理员专用的整页商城编辑器仍保留原权限，运营使用后台对应管理模块。

## 5. 商品批量导入

后台“商品批量导入”下载 CSV 模板（Excel 可打开），接受 UTF-8 CSV 或 XLSX 第一张普通工作表；不执行公式，含公式的文件会拒绝。单次最大 512 KB、1000 条商品。表头为 `id,name,price_cents,brand,category,active,sub,image`，价格单位为分。

选择“仅新增 / 仅更新 / 新增及更新”，先校验和预览，再确认执行。新商品默认下架，更新中空白字段保留原值，保留已有规格结构；子 SKU 不能冒充父商品覆盖。导入不更改库存。预览后 30 分钟内可提交，任务归创建员工所有；每批推进 25 行，页面显示进度并可下载完整逐行报告。预览后商品被别人修改时，该行失败，避免覆盖新资料。页面仅展示前 100 行，报告包含全部行。

普通商品保存与导入均在事务内验证编号归属，禁止父商品编号覆盖其他商品的子 SKU，也禁止生成的子 SKU 覆盖已有独立商品。生成后的规格编号最多 128 字节，超限在写入前拒绝。

## 6. 实时站内消息

登录后通过 `GET /api/v1/notification/stream` 订阅本人消息。使用请求头 Bearer 会话，不在 URL 放令牌；每 2 秒核验会话和消息变化，注销后终止。单连接最长 25 秒并自动重连，支持 Last-Event-ID，初始快照不重复弹提醒。每网关最多 256 个连接、每账号 2 个；页面隐藏时暂停。

收到新快照后更新未读数和消息页，并对新未读消息显示提醒。Nginx 专用路径关闭缓冲与压缩。该功能为站内消息，浏览器推送、短信和微信模板消息尚未接入。

连接停止或切换后，旧请求的迟到响应、失效提示和重连任务均不再影响当前会话。

## 7. 采购补货

后台“采购补货”创建含供应商、联系方式、SKU 数量和采购单价的采购单。审批后支持分批到货、损坏数及验收备注。每次收货在一个事务中记录验收人、采购进度、库存与流水；只有完好件进入可用库存。重复提交同一收货请求不会重复加库存，超量收货、过期版本和未审批入库会拒绝。采购结束前可填写原因取消未到货部分；不撤销已收货库存。详情展示最近 100 次验收及总次数。

## 8. 物流轨迹与异常件

会员在订单物流入口查看本人运单时间线；后台“物流轨迹与异常件”可查询轨迹、补充人工记录、登记异常处理结果。渠道回调验签后追加轨迹，乱序扫描不倒退当前状态，签收为终态。签收会同步解决未处理异常并保留原配送确认领域事件。

轨迹分页按事件发生时间排序，迟到的旧轨迹不会挤掉第一页的最新进展。已在运输中的包裹不会因后续创建类扫描回退为待揽收；并发重复签收返回同一已签收结果。

默认超过 24 小时未揽收、运输中超过 72 小时无新轨迹会生成异常；可用 `LOGISTICS_PICKUP_TIMEOUT_HOURS`、`LOGISTICS_STALE_TIMEOUT_HOURS` 调整（1–720 小时）。异常通过现有站内消息告知会员。签名回调、外部创建运单协议见 [carrier-adapter.md](carrier-adapter.md)。未配置外部渠道时仍明确使用演示物流；真实仓库出库适配仍需独立接入。

## 更新和回归

执行 `sh start.sh` 构建并更新受影响服务，保留现有数据卷。前台静态资源和后台服务必须一并更新；生成的 RPC 和前台常量已同步。

主要回归命令：`make test`、`make test-web`、`make test-browser`。浏览器用例覆盖游客合并、安全中心、员工权限、CSV 导入、采购部分收货及物流消息流程。`TestMySQLFeatureExpansionTransactions` 使用独立 scratch schema 验证迁移重入、密码撤销会话、导入、并发验收、并发物流回调和财务事实去重；启用方式沿用 README 中 MySQL 测试参数。
